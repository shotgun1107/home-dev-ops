# K12 Home DevOps

**AI 개발 작업의 지속성과 실행 권한을 관리하고 다른 사람과 컴퓨팅 자원을 나누기 위한 개인 서버 운영 연구**

개인 소유 K12 서버를 AI 개발 환경으로 운영하면서 작업 인계와 결과 검증 그리고 실패 복구를 다룹니다
장기적으로는 외부 이용자에게 VPS 형태로 자원을 제공할 수 있도록 관리 영역과 개발 환경 및 이용자 영역의 경계를 설계하고 있습니다

핵심 질문은 **AI에게 작업을 맡긴 뒤 무엇을 확인해야 다음 작업과 운영 단계로 넘어갈 수 있는가**입니다

[연구와 검증 근거 읽기](docs/research-guide.md) · [초기 운영 실험 기록][ops-status] · [실험 코드][ops-code]

| 운영 목표 | 지속 가능한 개인 개발 환경과 외부 이용자에게 자원을 제공할 수 있는 격리 구조 |
| 연구 범위 | 작업 인계 · 승인과 실행의 구분 · CI 검증 · 자원 예약 · 사용자 격리 · 복구와 감사 |
| 확인할 수 있는 산출물 | 운영 점검 도구와 회귀시험 · 논리 아키텍처 · 실패 재현과 수정 기록 · 검토와 인계 문서 |
| 주요 기반 | Linux · Python · Node.js · SQLite · GitHub Actions · Paseo |

현재는 **운영 실험과 논리 설계 및 구성요소별 구현·검증 단계**입니다
외부 이용자 서비스 개시와 목표 환경의 전체 운영 검증은 남아 있습니다

## 어떤 문제를 다루나

### 작업이 끊겨도 이어받을 수 있는가

AI 세션이 종료되거나 다른 도구로 교대할 때 코드와 실행 상태가 어긋날 수 있습니다
작업 범위와 담당자 그리고 Git 상태와 실행 환경을 함께 확인하는 인계 절차를 실험했습니다
초기 기록에는 단일 작업의 검증과 사람의 병합 이후 서버에서 결과를 확인한 사례 및 Claude에서 Codex로 순차 교대한 사례가 있습니다

→ [작업 인계와 검증 상태][ops-status]

### 성공 표시를 실제 검증으로 신뢰할 수 있는가

검사 프로세스가 실제 시험을 마치기 전에 성공 종료 코드를 반환하는 반례를 재현했습니다
실행한 시험 수와 완료 기록 및 입력 파일의 동일성을 확인하도록 검사 도구를 보완했습니다
실패한 가설과 수정 전의 반례도 근거로 보존했습니다

→ [반례 재현과 교정][ops-review] · [CI 검증 설계][ops-ci]

### 개발 작업과 운영 권한을 어떻게 나눌 것인가

작업 요청에 대한 허용 응답과 실제 실행 결과를 따로 기록하고 누가 어떤 근거로 결정했는지 추적합니다
개발 환경과 관리 제어 영역 및 외부 이용자 영역의 경계를 논리적으로 나누고 권한 확대와 자원 회수의 조건을 정의했습니다

→ [승인 기록을 검토하는 도구와 한계][ops-permissions] · [후속 격리 연구](docs/research-guide.md#후속-격리-연구)

### 실패하거나 응답이 늦어져도 상태를 지킬 수 있는가

후속 GREEN 연구에서는 프로세스 사망 뒤의 자원 예약 유지와 늦은 응답의 상태 덮어쓰기 그리고 이용자 자원 회수 조건을 다뤘습니다
정상 동작과 실패 주입 및 별도 검토 결과를 연결해 각 수정의 수용 범위를 기록했습니다

→ [자원 예약과 상태 관리 사례](docs/research-guide.md#후속-격리-연구)

## 설계의 큰 구조

| 영역 | 책임 | 주요 판단 기준 |
| --- | --- | --- |
| 실행 기반 | 실행 자원과 저장소 및 네트워크의 경계 | 소유권과 예약 상태를 확인한 뒤 할당·회수 |
| 관리 제어 | 신원과 정책 및 감사 기록 | 관리 권한과 일반 작업 권한을 분리 |
| 개발 환경 | AI 개발 세션과 작업별 실행 공간 | 담당자와 작업 상태를 확인한 뒤 인계 |
| 개인 서비스 | 빌드 결과와 배포·복구 과정 | 검증한 산출물과 승인 대상의 일치 |
| 외부 이용자 | 신청과 할당 및 실행·만료 상태 | 이용자 간 격리와 자원별 권한·기한 |

위 표는 2026년 10월 20일 채택된 논리 설계의 요약입니다
실제 배치와 전체 통합 검증 여부는 [연구 단계와 근거](docs/research-guide.md)에서 별도로 확인할 수 있습니다

## 검증 기록을 읽는 기준

| 구분 | 확인된 기록 | 남은 범위 |
| --- | --- | --- |
| 10월 10일 초기 운영 실험 | Python 시험 133개 실행 기록과 별도 인계·권한·복구 사례 | 전체 운영 완료와 무인 운영 효과 |
| 10월 20일 논리 설계 | 격리와 권한 경계 및 단계별 검증 조건의 기준선 채택 | 실제 호스트의 안전성과 운영 성능 |
| 10월 30~31일 GREEN 후속 연구 | 구성요소별 수정과 제한된 시험·검토 결과 | 목표 환경 통합과 공식 수락 검사 및 외부 이용자 개시 |

실험과 실행 환경이 다른 시험 수는 합산하지 않습니다
기능 브랜치의 검증 결과와 운영 환경에 적용된 상태도 구분합니다
이 소개 문서의 정리는 새 운영 시험을 실행한 결과가 아닙니다
