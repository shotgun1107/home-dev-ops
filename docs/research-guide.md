# K12 연구와 검증 근거 안내

[프로젝트 소개로 돌아가기](../README.md)

이 문서는 초기 Paseo 운영 실험과 이후 별도 연구 환경 GREEN에서 수행한 격리 아키텍처 연구를 연결하는 읽기 안내입니다
서로 다른 시점과 실행 환경의 기록을 구분하고 각 결과가 어디까지 확인됐는지 설명합니다
정리 기준일은 2026년 11월 9일이며 운영 시스템을 새로 관측하거나 시험한 문서는 아닙니다

## 연구의 흐름

| 단계 | 출발한 문제 | 남긴 근거 |
| --- | --- | --- |
| 초기 운영 실험 | AI 작업을 중단·교대해도 상태와 책임을 이어받을 수 있는가 | 작업 인계와 승인 기록 및 복구·CI 점검 도구 |
| 논리 아키텍처 | 관리와 개발 및 외부 이용자의 실행 권한을 어떻게 나눌 것인가 | 2026년 10월 20일 채택한 v1.4.3.1 기준선 |
| 후속 GREEN 연구 | 장애와 늦은 응답 및 불확실한 자원 상태에서 어떤 동작을 허용할 것인가 | 구성요소별 구현 후보와 실패 주입·수정·별도 검토 기록 |

장기 목표는 개인 개발 환경을 안정적으로 운영하고 외부 이용자에게 컴퓨팅 자원을 제공하는 것입니다
외부 이용자 도입과 실제 운영 전환은 후속 검증 단계로 남아 있습니다

## 초기 운영 실험

### 성공 종료와 실제 검사 완료를 구분한 사례

검사 명령이 성공 코드로 끝났더라도 의도한 시험이 모두 실행됐는지는 별도 확인이 필요했습니다
하위 프로세스가 검사를 끝내기 전에 종료하는 반례를 재현하고 부모 프로세스가 실제 실행 수와 완료 기록을 대조하도록 보완했습니다
입력 대기와 잘못된 자료형도 반례로 확인해 회귀시험에 반영했습니다

이 사례의 핵심은 검사 결과의 표시를 신뢰하기 전에 검사 과정 자체를 검증한 점입니다

- [독립 리뷰와 반례 교정](https://github.com/shotgun1107/home-dev-ops/blob/adddce321ded60b99eef76e5b1430225e6bd7b94/docs/k12-paseo/INDEPENDENT_REVIEW.md)
- [CI 설계와 실행 범위](https://github.com/shotgun1107/home-dev-ops/blob/adddce321ded60b99eef76e5b1430225e6bd7b94/docs/k12-paseo/OPS_CI.md)
- [검사 실행기 소스](https://github.com/shotgun1107/home-dev-ops/blob/adddce321ded60b99eef76e5b1430225e6bd7b94/scripts/run_ops_ci.py)

### 인계와 승인 기록을 분리한 사례

다른 AI 도구가 작업을 이어받기 전에 이전 실행의 종료와 Git 상태 및 실행 환경을 대조했습니다
승인 요청에 대한 허용 응답과 실제 실행의 시작·성공을 구분해 집계하는 점검 도구도 작성했습니다

- [초기 단계별 검증 현황](https://github.com/shotgun1107/home-dev-ops/blob/adddce321ded60b99eef76e5b1430225e6bd7b94/docs/k12-paseo/STATUS.md)
- [권한 라우팅과 기록 감사](https://github.com/shotgun1107/home-dev-ops/blob/adddce321ded60b99eef76e5b1430225e6bd7b94/docs/k12-paseo/PERMISSIONS.md)

10월 10일 기록의 Python 시험 133개는 해당 시험 집합의 실행 결과입니다
별도 Node 검사와 mock 실행 수를 합산하거나 전체 운영 자격으로 해석하지 않습니다
이 자료는 기능 브랜치의 기록이며 해당 코드의 main 채택과 운영 배포를 뜻하지 않습니다

## 후속 격리 연구

다음 사례는 `K12_GREEN_ALL_RESULTS_20261031.zip` 안의 10월 30일 후속 인계 문서를 읽고 요약했습니다
이 묶음은 결과 문서 사본이며 원본 코드와 대용량 실행 로그는 포함하지 않습니다

| 문제 | 연구한 대응 | 확인 범위와 남은 조건 |
| --- | --- | --- |
| 관리 프로세스가 죽어도 하위 작업이 자원을 사용할 수 있음 | 후손 프로세스의 생존과 불확실한 예약 상태를 확인하고 새 할당을 보류 | P0 r2의 실패 주입과 별도 검토 범위에서 수용 |
| 늦은 응답이 종료·보류 상태를 덮어쓸 수 있음 | SQLite 쓰기 트랜잭션 안에서 요청과 세대 및 현재 상태를 재검사 | C63 r1의 양성 시험과 표적 변이 검사 범위에서 수용 |
| 이용자 자원을 일부만 확인하고 회수 완료로 처리할 수 있음 | 전체 자원 목록과 회수 상태 및 독립적인 부재 기록을 대조 | P4 r4의 분리된 실험용 연결 계층에서 검증했으며 실제 운영 연결은 남음 |
| 파일 공개 이후의 변경이나 동기화 누락을 놓칠 수 있음 | 파일 수명과 쓰기·동기화·공개 순서를 검사 | HTTPS r4가 지원하는 절차 안에서 검증했으며 범위 밖 별칭 사용은 거부 |

정상 시험을 통과한 뒤 별도 검토에서 새로운 반례가 발견된 사례도 있습니다
P0의 예약 상태와 P4의 회수 조건 및 HTTPS의 파일 변경 검사는 실패를 보존한 뒤 수정 후보를 다시 검토했습니다
시험 오류와 timeout을 정상 통과나 변이 검출로 계산하지 않는 기준을 유지했습니다

## 설계 채택과 운영 검증의 구분

논리 아키텍처 v1.4.3.1은 가정과 권한 경계 및 상태 전이와 검증 조건의 기준선입니다
채택 기록은 실제 환경의 안전성이나 성능을 입증한 결과가 아닙니다

| 상태 | 의미 | 10월 말 원본에 기록된 상태 |
| --- | --- | --- |
| 논리 설계 채택 | 후속 구현을 검토할 기준선 확정 | 2026년 10월 20일 채택 |
| GREEN의 제한 범위 수용 | 지정된 소스와 시험 및 검토 범위의 수용 | 구성요소별 PASS_SCOPE와 해당 제한 기록 |
| 공식 수락 검사 | 목표 환경에서 기능과 경계 및 운영 조건 확인 | A 27개 · T 12개 · EP 20개 모두 NOT_RUN |
| 사람의 병합과 배포 승인 | 정확한 변경과 산출물을 운영에 반영하는 판단 | G1 HUMAN_ONLY / NOT_RUN · G3 HOLD |

후속 과제는 실제 목표 환경과 연결한 검증 및 복원 확인 그리고 외부 이용자 개시 조건의 충족입니다
운영 환경에서 확인되지 않은 상태는 과거 실험 결과로 대신하지 않습니다
